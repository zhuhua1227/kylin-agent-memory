## PersonaChat

- **确定版本**：原始版 Zhang et al. 2018（ACL），后续 ConvAI2 竞赛沿用并发布过"revised persona"修订版。
- **规模**：1,155 个不同 persona（每个 4~8 句话），10,907 段对话，超 162,000 句 utterance；100 个 persona 留验证、100 个留测试。
- **一手来源**：论文 *Personalizing Dialogue Agents: I have a dog, do you have pets too?*，<https://arxiv.org/abs/1801.07243>，全文 PDF <https://arxiv.org/pdf/1801.07243>（访问日期 2026-08-26）。
- **依据出处**：论文 Section 3（Data Collection）。

| 属性 | 结论 | 依据 | 是读到的还是推断的 |
|---|---|---|---|
| P1 跨会话延续性 | **与原判断有出入**：Section 3 原文说明每个 persona 会参与多段不同对话（"each persona participated in multiple conversations"），理论上可以靠 persona 文本内容把同一"人设"的多段对话关联起来。但这不是数据集设计出来的显式 ID 字段，而是文本复用的副产品；配对是随机的（"Workers were randomly paired for each conversation"），不构成"同一主体在不同时间点"的连续记忆演化。结论：**存在弱隐式关联，但非设计出的会话延续机制**，不能简单记成"无" | 论文 Section 3 原文引用 | 读到 |
| P2 时间维度 | 无。Section 3 未提供时间戳字段 | 论文 Section 3 | 读到 |
| P3 偏好来源 | **确认成立**：persona 是众包工人预先编写的 4~8 句静态简介，直接分配给说话人使用，不是从行为轨迹里挖掘出来的（Section 3 原文 "Workers wrote between 4 and 8 sentences describing a persona they invented"）；另有为消除逻辑冲突而产生的"revised persona"，但仍是人工编写的静态标签，不是行为挖掘结果 | 论文 Section 3 原文引用 | 读到 |
| P4 知识版本关系 | 无。"revised persona" 是标注质量修正（消除前后矛盾），不是"新知识取代旧知识"意义上的版本演化，两者概念不同 | 论文 Section 3 | 推断 |
| P5 操作层面 | 闲聊对话文本，非 OS 操作层面 | 论文摘要 | 读到 |

**与原断言的出入**：P3（较高把握）被证实成立；**P1 需要修正**——原表格判断"无同一主体跨天延续"，实际是"有 persona 复用产生的弱隐式关联，但没有时间顺序、也不是刻意设计的延续机制"，两者不完全一样，如实记录这处出入。

## TREC

- **性质核实**：TREC（Text REtrieval Conference）是 NIST 主办的年度信息检索评测会议系列，不是单一数据集。官方数据页 <https://trec.nist.gov/data.html>（访问日期 2026-08-26）列出的 track 数量在 70 个以上，跨越从 1992 年至今的多个年度。
- **原表格断言处理**：原断言"TREC 只有 query-document 对，没有版本维度"作为对 TREC 整体的断言**确定是错的**——但错误的准确性质是"断言粒度错了"，不是"结论方向错了"。必须限定到具体 track 分别说：

### TREC Deep Learning Track（与我们任务最相关的 query-passage 相关性范式）

- **一手来源**：track 官方指南 <https://microsoft.github.io/msmarco/TREC-Deep-Learning-2020.html>；2019 年首届 Overview 报告 <https://trec.nist.gov/pubs/trec28/papers/OVERVIEW.DL.pdf>（访问日期均 2026-08-26）。
- **结论**：该 track 自 2019 年起每年基于 MS MARCO 语料构建 passage/document ranking 与 re-ranking 两个任务，产出静态的人工 qrels（相关性判断），是"只有 query-document/passage 相关性对，没有条目级版本取代关系"这句话最贴切的对象——**如果把这句话限定到"TREC Deep Learning Track 的相关性判断本身"，基本成立**（读到）。
- **一个需要单独说明的细节**：2021 年该 track 做过一次语料"corpus refresh"，passage 集合从约 880 万条扩容到约 1.4 亿条量级（约 16 倍）。这是**整个语料库换代**（不同年份用不同版本的底层语料库），不是"某一条知识被新知识取代"意义上的版本关系——两者要分清，不能拿"语料库换过版本"去支持我们任务需要的"知识条目被取代"这种版本维度（读到 + 推断）。

### 确实存在具时效性的 track（验证了原方案"主动检索是否存在这类 track"的要求）

- **TREC Temporal Summarization**（2013~2015）：追踪突发新闻事件（灾害、事故、抗议等）随时间推移出现的新信息，产出"时序更新摘要"。一手来源：2013 年 Overview <https://trec.nist.gov/pubs/trec22/papers/TS.OVERVIEW.pdf>（访问日期 2026-08-26）。
- **TREC Real-Time Summarization**（2016 年起，由 Temporal Summarization 与 Microblog track 合并而来）：面向社交媒体流的实时演化信息摘要。一手来源：<https://trec.nist.gov/pubs/trec25/papers/Overview-RT.pdf>（访问日期 2026-08-26）。
- **TREC Incident Streams**（2018 年起）：对社交媒体上的危机响应信息流做分类与优先级判断。一手来源：McCreadie et al., *TREC Incident Streams: Finding Actionable Information on Social Media*，<https://idl.iscram.org/files/richardmccreadie/2019/1867_RichardMcCreadie_etal2019.pdf>（访问日期 2026-08-26）。
- **这几个 track 确有 P2 时间维度，但语义上不是我们要的 P4**：它们建模的是"同一个外部事件（如一场地震）在几小时到几天内持续演化出新信息"，本质是**事件流/信息增量**，不是"同一条知识被判定过时并被新知识替换"。两者都涉及时间，但前者是外部世界的事件在滚动更新，后者是同一认知主体对某个事实的记忆被修正——这个区分原方案已经预判到了（"它的时效性是'事件演化'不是'知识被取代'"），核实后确认这个预判是对的（读到 + 推断）。

**与原断言的出入**：原表格"🔴认为这条是错的"的直觉方向正确，但需要修正为——不是"TREC 的说法整体错了所以整体不成立"，而是"作为整体断言，TREC 这个说法本身问法就有问题；限定到 TREC Deep Learning Track 后，这句话基本是对的；同时 TREC 系列里确实存在若干具时效性的 track，但它们的时效性属于事件演化,不属于知识版本取代"。三层结论都要写进技术方案,不能只写一层。

## MS MARCO

- **确定版本**：原始论文 Nguyen et al., *MS MARCO: A Human Generated MAchine Reading COmprehension Dataset*，2016；现在主要活跃的是其下的 Passage Ranking / Document Ranking 子任务。
- **规模**：原始约 101 万条匿名问题（采样自 Bing 搜索查询日志），Passage Ranking 语料约 880 万段落，Document Ranking 语料约 320 万文档（经典版本）。
- **一手来源**：
  - 原始论文：<https://arxiv.org/abs/1611.09268>（访问日期 2026-08-26）
  - 官方站点：<https://microsoft.github.io/msmarco/>（访问日期 2026-08-26）
  - 官方数据集清单：<https://github.com/microsoft/msmarco/blob/master/Datasets.md>
- **依据出处**：论文摘要（规模与匿名化处理）；官方站点任务列表。

| 属性 | 结论 | 依据 | 是读到的还是推断的 |
|---|---|---|---|
| P1 跨会话延续性 | 无。查询已做匿名化处理（论文摘要原文 "anonymized questions"），论文与官网均未提供可追踪同一用户跨会话的字段 | 论文摘要 | 读到 |
| P2 时间维度 | 经典 Passage/Document Ranking 任务无时间戳。**需要单独说明的例外**：官方站点另有 2019 年 4 月发布的 "Conversational Search" 子任务，原文写"we have released a large corpus of anonymized user search sessions"（一批匿名用户搜索会话语料），具有会话内部的多轮上下文结构——这是原表格完全没覆盖到的一个子集，说明"MS MARCO"实际是个数据集家族，不是单一数据集，只是这个问题不像 ToolBench/TREC 那样严重（读到） | 官方站点任务列表原文引用 | 读到 |
| P3 偏好来源 | 不适用。检索相关性数据，无偏好概念 | — | 推断 |
| P4 知识版本关系 | 无。相关性判断是一次性人工标注，官网未提及文档/段落存在版本取代关系 | 官方站点 | 读到 |
| P5 操作层面 | 网页搜索的 query-passage/document 相关性，非 OS 操作层面 | 论文摘要 | 读到 |

**与原断言的出入**：主体判断成立（原"把握=中"，核实后可上调为"把握=高"，针对经典 Passage/Document Ranking 任务）；但需要补一句原表格没有的说明——MS MARCO 官方站点下还有一个"Conversational Search"会话语料子集，具备会话内部多轮结构，这一点在写技术方案时要避免被误读成"MS MARCO 完全没有会话概念"这种整体性断言。
