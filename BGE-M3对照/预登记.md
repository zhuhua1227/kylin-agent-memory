## 三、三个会静默毁掉对比的坑，本次怎么处理（跑前定）

### 3.1 L2 归一化
- `retrieve.py` 对**两侧**都无条件 `l2norm()` 再算余弦（已写进代码，第 27 行）。
- Kylin 侧固化向量是 KYSDK 原始输出（`fixate_vectors.py` 未归一化），retrieve.py 归一化它。
- BGE 侧同样：拿到 dense 向量后由 retrieve.py 归一化，`make_vectors_bge.py` 不自己归一化。
- 报告写明"两侧算余弦前均显式 L2 归一化"。

### 3.2 BGE-M3 只用 dense
- `model.encode(texts, return_dense=True, return_sparse=False, return_colbert_vecs=False)`。
- 不用 sparse / colbert，不做多向量混合（那是拿集成方法比单编码器）。

### 3.3 截断长度
- 先统计 `texts.jsonl` 里 86 条 doc 的**字符数与（用 BGE tokenizer 的）token 数**分布。
- 查系统 KYSDK embedding 的输入上限（`向量化常驻服务` 报告 / `embedding_client` 的告警阈值，
  实测见过 "输入长度 X 字符超过安全阈值 200" 的告警 —— 但那是**告警不是硬截断**，
  需确认 KYSDK 实际有没有截、截在哪）。
- **一条都不超 BGE 的 8192 上限**（doc 最长约 900 字符，远低于）→ BGE 侧不截断，报告写明"BGE 侧无截断"。
- 若系统侧实际发生过截断：两个口径都报 —— ① 同输入（两侧都截到系统上限）headline；② 原生（各用各上限）附报。
  **但系统侧向量已固化、无法重算**，所以只能：如实说明系统侧固化时的输入长度分布 + 是否触发过 KYSDK 截断，
  BGE 侧按"与系统固化时相同的输入文本"编码（就是 `texts.jsonl` 原文，不额外截）。

### 3.4 指令前缀
- BGE-M3 **不需要** BGE-v1.5 那种 `"为这个句子生成表示以用于检索文章："` 前缀（加了掉点）。
- 跑前查当前 `FlagEmbedding` 版本文档确认，报告写明"未加任何指令前缀"。
