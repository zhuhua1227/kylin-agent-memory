# BGE-M3 对照 · 复现

> ★ 重点是**可证伪**：下面三条命令任何人在自己机器上跑一遍，一旦得到不同结果，我们全盘皆输。
> 不需要银河麒麟、不需要 GPU、不需要联网（BGE 向量已固化在 `docs_bge.npy` / `queries_bge.npy`）。

## 最短路径

```bash
pip install numpy
cd BGE-M3对照
python retrieve.py --side kylin     # ① 系统侧：当场核对 C-265 / C-266 两个锚定值
python retrieve.py --side bge       # ② BGE-M3 侧
python retrieve.py --mcnemar        # ③ 配对不一致对
```

`retrieve.py --side kylin` 跑完必须看到：

```
R@1: 实测 0.5242  vs 锚定 0.5242   ✅ 逐位一致
R@10: 实测 0.8634  vs 锚定 0.8634   ✅ 逐位一致
✅ 自检通过：retrieve.py 正确，可以继续做 BGE 侧。
```

**对不上就说明 `retrieve.py` 错了**（脚本会直接 `SystemExit`），BGE 那侧的数不用看。

## 从头重算（含 BGE 向量生成，需 FlagEmbedding）

```bash
# ① 抽输入（从冻结产物）
python 00_build_inputs.py

# ② BGE 向量（在有 FlagEmbedding 的机器上，约 5 分钟 CPU）
#    需先拉 _knowledge_docs_frozen.jsonl（= /data/RAG/RAG/知识检索/knowledge_docs.jsonl，filehash d253231a…）
HF_HOME=<cache> HF_ENDPOINT=https://hf-mirror.com python make_vectors_bge.py

# ③ 检索计分
python retrieve.py --side kylin && python retrieve.py --side bge && python retrieve.py --mcnemar

# ④（可选）重新生成测量记录
python make_record.py
```

## 会看到什么

| 指标 | 系统 kylin-coreai-embedding | BGE-M3 dense |
|---|---|---|
| R@1 | 52.42% (119/227) | 50.66% (115/227) |
| R@3 | 76.21% (173/227) | 70.04% (159/227) |
| R@5 | 82.38% (187/227) | 77.09% (175/227) |
| R@10 | 86.34% (196/227) | 87.22% (198/227) |

McNemar R@10：只系统 14 / 只 BGE 16（无方向）。**结论：R@10 基本持平（对照实验预登记的结果 B）。**

## 文件清单

| 文件 | 是什么 |
|---|---|
| `预登记.md` | 跑前预登记（三种结果的解释写死，早于结果文件） |

| `perquery_{kylin,bge}.json` | 逐题名次与 top-10 |
| `_bge_meta.json` | BGE 侧配置与 token 长度统计 |
| `measurement_record_M-211.json` | M-211 风格测量记录（可搬进 `可复现性体系/records/`） |
| `results.md` / `说明报告.md` | 结果表 / 说明报告 |
