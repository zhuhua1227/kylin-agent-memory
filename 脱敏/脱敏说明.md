## 二、23 处「真实姓名/主机名」：锚定机制的承重项

命中集中在两个文件，且**早已被本项目的防泄漏检测器登记为设计内公开**
（`可复现性体系/test_detectors.py` 的 `BY_DESIGN` 表）：

| 文件 | 处数 | 登记理由（引自 `test_detectors.py`） |
|---|---|---|
| `可复现性体系/anchor_issue_snapshot.json` | 20 | GitHub issue 锚定快照，**URL 与作者字段必须可被第三方公开核验**；表内该项即 GitHub 用户名，随仓库 URL 天然公开 |
| `评测集/说明报告.md` | 3 | 正文引用上述锚定 issue 的地址，同上 |

### 为什么不能删

本项目的时间戳锚定依赖公开可查的 GitHub issue：**第三方要凭这个用户名与 URL
去 GitHub 核验该 issue 确实存在、确实发布于所声称的时间**。

**删掉它，锚定就不可核验了**——那等于为了形式上的"干净"，拆掉证据链上的一环。
该用户名本身随仓库 URL 天然公开，删除并不会带来任何隐私收益。

`scan_identity.py` 已同步这份 `BY_DESIGN`，命中标注为「设计内公开」且不计入残留。
**两处若不一致，以 `test_detectors.py` 为准。**

## 三、保留项的逐条定性

### 3.1 十六进制串（16 处，其中 11 处在冻结文件内）

| 命中形态 | 是什么 | 实际风险 |
|---|---|---|
| 40 位（`a638…b080`、`129f…44d5`） | GitHub OAuth **device_code** | 一次性授权码，**约 15 分钟即过期**，采集于 2026 年 8 月前，早已失效，无法用于任何访问 |
| 20 位（`178c…1d6a`） | GitHub OAuth **client_id** | **设计上即公开**——它出现在每一个 OAuth 授权 URL 中，本就不是机密（机密的是 client_secret，本仓无） |

**两者都不构成可利用的凭据。**

这些串出现在语料与评测集中，是因为它们本身就是被记录的**故障案例内容**
（一次 GitHub 设备流授权的排错过程）。

### 3.2 内网地址（21 处）

全部为 **RFC1918 私有地址段**，**不可路由**，不构成任何外部访问途径。
本仓已对绝大多数地址做了占位替换，这些是既有替换的漏网项。

**处置：整批保留并在此登记。** 未做部分替换——
**部分脱敏会造成同一实体在不同文件中指代不一致，反而为相关性反推提供入口**，
比统一保留更糟。

### 3.3 🔴 为什么冻结文件里的命中不予改动

`.gitattributes` 标记为 `binary` 的 **17 个文件字节不得变更**。
它们是 `可复现性体系/claims.json` 中 **122 条主张**的锚：

```
改动任意一个字节
  → generate_manifest.py 计算的 sha256 与 claims.json 中锚定值失配
  → reproduce_L1.py 全面报红
  → 「规则先于数据、评测集先于结果」这条论证当场失效
```

**权衡**：一侧是四项**均已失效或本就公开**的标识（§3.1、§3.2），
另一侧是整套可复现性体系的完整性。**我们选择保全后者，并在此公开登记前者。**

这是一个明示的取舍，不是遗漏。

## 四、两处刻意不处理的"命中"

### 4.1 脱敏器自身的测试夹具

```
多源数据整合/anonymize.py
多源数据整合/labeled_redaction_testset.json
```

其中的邮箱、手机号等**全部是合成数据**（`@example.com` 域名等），
用途是 `anonymize.py` 自身的断言：

```python
assert "<合成手机号>" not in json.dumps(cleaned), "手机号未脱敏！"
```

**把它们"脱敏"掉，等于把脱敏器的测试用例删掉。**
扫描器已将这两个文件列入 `FIXTURES` 永久跳过。

### 4.2 Shell 变量引用

`证明向量维度/restore_env*.sh` 中形如 `PW='$KYLIN_SSH_PW'` 的赋值
是**变量引用，不是明文口令**。扫描器的密钥模式已排除以 `$` 开头的取值。

## 五、工具自身的纪律：检查器不得内联待查值

`test_detectors.py` 中留有这样一条注记：

> ⚠️ 用序号而不是值本身：这份源码是受跟踪文件，写值进来就等于
> 在防泄漏检查器里泄漏一次——第一/二/三轮已经在同一个文件上犯过三次。

`scan_identity.py` 初版重蹈了此覆辙（把姓名正则内联进源码），**已修正**：

```
身份类词根  →  脱敏/patterns.local.txt（已加入 .gitignore，不进提交物）
通用类规则  →  留在源码（地址段、十六进制长度等，不含可识别字面量）
```

词表缺失时，扫描器**明确报出"身份类规则本次未扫描"**，
而不是静默地把结果当作"没问题"——**沉默的降级比报错更危险**。

本文件亦遵循同一纪律（见文首提示）。
