# 模型消融 4×2 · 实验方案

> **模型**：`Qwen3.5-2B / 4B / 9B`（Q4_K_M，麒麟本机）· `Kimi-K3`（云端）
> **条件**：有记忆 / 无记忆
> **交给谁**：实现 Agent。任务集草案见 §三，需按 §3.3 补齐后再跑。
> **时间盒**：2 天。

---

## 〇、八格与决胜论点

### 0.1 格局

| | 无记忆 | 有记忆 |
|---|---|---|
| **Qwen3.5-2B** | **A1** | **A2** ★ 关键格 |
| **Qwen3.5-4B** | **B1** | **B2** |
| **Qwen3.5-9B** | **C1** | **C2** |
| **Kimi-K3**（云端） | **K1** ★ 对照基准 | **K2** 上界 |

### 0.2 选型：Qwen3.5 Dense 三档

```
小档  Qwen3.5-2B      中档  Qwen3.5-4B      大档  Qwen3.5-9B
```

**同代、同族、全 Dense**，间距接近等比（2→4→9）——规模是唯一变量，趋势也读得出来。

**❌ 不要把 MoE 档（`35B-A3B` / `122B-A10B`）放进阶梯。**
它们的总参数与激活参数不是一回事，混进来会毁掉「规模」这个变量的含义。

### 0.2b 🔴 量化档统一 Q4_K_M

```
Qwen3.5-2B  Q4_K_M  ≈ 1.3 GB
Qwen3.5-4B  Q4_K_M  ≈ 2.5 GB
Qwen3.5-9B  Q4_K_M  ≈ 5.6 GB
```

**不要为了小档能上 Q8 就让 9B 单独降档**——量化档必须在阶梯上恒定，
否则混进第二个变量。合计下载约 9.4 GB，**落在 `/data`**。

### 0.2c ⚠️ 锁死 thinking 模式

Qwen3.5 若有 thinking / non-thinking 两种模式，**八格必须锁同一种**。

**建议关掉**——2B 会把有限的生成预算烧在思考链上，答案反而更差；
且本任务集是「答一条命令」，不需要推理链。在报告里写明用的哪种。

### 0.3 三条要读的线

```
主论点   A2 ≥ K1        2B+记忆  追平/超过  云端大模型无记忆
张力题   A2 vs K2       2B+记忆     对      云端大模型+记忆     ← 真正有信息量的一对
阶梯     Δ(2B) Δ(4B) Δ(9B) Δ(K3)         Δ = 同一行「有记忆 − 无记忆」
```

**为什么「张力题」才是重点**：这 13 条是**任何模型都猜不到**的环境特异事实，
所以无记忆的四格（A1/B1/C1/K1）预计都接近 0~2/13，**K1 本身就很低**。
主论点因此赢得偏轻松、信息量有限。真正难的是 `A2 vs K2`——
**2B 能不能把注入的记忆用得跟云端大模型一样好。**

### 0.3b 🔴 不要预设 Δ 的方向

我原先写过「Δ 随规模递减（模型越弱记忆越顶用）」。**按现在的任务设计，这大概率是错的**：

这 13 条题本质是「把注入进来的事实抄出来」，**2B 的阅读理解就够用了**。所以真实预期更可能是：

```
无记忆组   四档都  0~2/13     环境事实谁也猜不到
有记忆组   四档都 10~13/13    抄出来而已
Δ          四档基本持平
```

**而 Δ 持平恰恰是好结果**——它说明**记忆机制的收益不依赖模型规模，2B 就能吃满**，
这直接就是端侧部署的论据，比「Δ 递减」更有用。

**所以两种结果都要能解释，不许预设方向，更不许事后挑一个说成「符合预期」。**
出结果前把两种解释都写下来，跑完只做填空。

### 0.4 ⚠️ 加模型补不了样本量

八格仍然共用**同一批 13 条题**。格子从 4 个变 8 个，
**能做的两两比较变多了，样本量一条没多**，多重比较的风险反而上升。

**不要因为格子多就觉得证据多。** 统计口径仍按 §四：只作描述性表述。

### 0.5 🔴 运行环境：三档本地模型跑在麒麟虚拟机上（CPU）

**选虚拟机不是为了叙事，是因为这个工作量不需要显卡。**

```
13 题 × 2 条件 × 3 档 = 78 次生成
每次输出约 200 token → 合计约 1.6 万 token
记忆注入 prefill 每次约 1500 token × 78 ≈ 12 万 token

9B Q4_K_M 纯 CPU：生成 2~4 tok/s、prefill 20~40 tok/s
→ 最慢那一档约 1 小时，三档全跑完 2 小时以内
```

为省这一小时换掉叙事不划算。显存那边也没有优势：8 GB 跑 9B Q4_K_M（5.6 GB + KV cache）
本来就紧，还要跟本机另外两套 ComfyUI 抢卡。

**12 GB 内存装得下全部三档**——最大那档加 8k 上下文约 7 GB。

**叙事收益是具体的**：赛题是「OS Agent 记忆优化」，端侧模型跑在麒麟上，
是「方案在目标平台端到端可用」的直接证据；演示视频也正需要这个画面。
且仓库本就在 `/data/RAG/RAG`，检索服务与模型同机，少一跳网络。

#### 三条约束

```
① 模型文件与 llama.cpp 放 /home 或 /data，不要放 /usr（重启回滚）
② 三档必须同机、同运行时（同一份 llama.cpp）、同量化档、同 top-k、同温度
③ 先确认 PVE 宿主匀得出 12 GB 给这台 VM
```

#### ⚠️ `wall_ms` 不能跨类比较

CPU 生成耗时与 Kimi 的网络往返不是一类东西。
**该字段只用于同机三档之间的相对比较**，不许拿去跟 K 行比，也不许写成「本方案比云端快」。

#### 撤退条件（写死，不靠临场判断）

先用 9B 实测**单题耗时**：

```
≤ 5 分钟/题   → 照跑（78 题 ≈ 6.5 小时以内，可接受）
>  5 分钟/题  → 才考虑搬到笔记本 GPU
```

搬的话**整个阶梯一起搬**。**绝不能只把 9B 挪到笔记本**——那会当场破坏约束 ②。

## 一、🔴 语料实况决定了任务只能是「回答型」

实际索引：31 案例 + 54 流程 + 1 模板 = 86 条。案例里约 13 条是 plink/pscp 传命令的坑，
其余是 Windows 路径、工具 schema 约束、时序问题。**D1–D7 采集未产出任何新知识单元**，
所以麒麟侧的环境事实（`share-kytensor-*`、`/usr` overlay）**不在索引里，不能出成题**。

### 由此定三条

**① 全部做成「回答型」，不做执行型。**

```
✅ 「SSH 到 <host> 密码认证被拒，你会用什么命令？」        → 只要答案文本
❌ 「去把 sshd 起来」                                      → 需要真执行
```

三个理由，缺一不可：

- 语料里的知识**大多涉及 SSH 到其他机器并带凭据**，执行型会真去连别的机器
- **2B 基本做不了工具编排**。若两组都因编排失败拿 0 分，实验退化成噪声、什么也测不出
- 回答型的评分是纯字符串匹配，**零 LLM 裁判**

**② 砍掉原设计的 B 类（沙箱状态达成）与 C 类（多步效率）。**
两者都要求执行，与 ① 冲突。**代价是本实验测的是「知识可得性」而非「执行效率」**，
须写进已知限制——不要含糊过去。

**③ 剔除通识题。** `netstat`→`ss`、`sqlite3` 未装→`python3 -c "import sqlite3"`
这类任何模型都会，**无记忆组照样答对，测不出差异**，反而稀释真实效应。

## 二、运行协议（控制变量）

```
system prompt、任务文本、可用工具              八格逐字相同（跨条件也跨模型）
无记忆组 = 【不调 /retrieve 接口】               不是删掉一段提示词
每题独立会话                                     不许前一题的上下文帮到后一题
温度固定 0，随机种子固定                          四行都要
每格每题只跑一次                                 不取多次最优
```

**注入格式**（沿用批次一已验证的）：

```

```

每次运行落一条 `runs.jsonl`：

```json
 "answer_text":"...","injected_doc_ids":[12,45],"retrieval_config":"all",
 "wall_ms":4130,"error":null}
```

## 三、任务集

### 3.1 格式

```json
{"task_id":"T-001","type":"A",
 "prompt":"...",
 "must_contain":["..."],
 "must_not_contain":["..."],
 "source_unit":"case-06"}
```

`must_not_contain` **不是可选项**——它抓的正是「没有记忆时最容易给出的那个错答案」，
是这类题真正的区分器。**每条必须有。**

### 3.2 🔴 出题前必读：报错原文会泄答案

本项目的报错文本里，**有些直接把正确答案印在里面**。最典型的是 case 17：

```
InputValidationError: [{ "code":"invalid_value", "values":["proactive"], "path":["status"] ... }]
```

题干若照抄这段，**无记忆组也能 100% 答对**，这道题就白出了。

**规则：题干里的报错必须裁到「只保留症状、不含修法」。**
上面这条应裁成「调用 PushNotification 时 `status` 字段报 InputValidationError」。

每出一条题，问一句：**把记忆拿掉，光看题干能不能推出答案？** 能 → 重裁题干或弃题。

### 3.4 n = 13 就是上限（workflow 已查过，补不了）

54 条 workflow 的结构是 `intent` + `tool_sequence`，其中 `input_summary` 是英文自由文本
（如 `"Check availability of ssh/sshpass/plink"`）。拿它出题会同时踩两个坑：

```
① 答案不唯一 —— 排查顺序有多种合理走法，判不了对错
② 无法字符串匹配 —— 只能上 LLM 裁判，与 §四 的硬要求冲突
```

且有相当比例的 `intent` 本身被截断成 `[Pasted text #1 +7 lines]`，题干都凑不出来。

**结论：任务集就是 13 条，不再扩。** 若实现时确实从剩余案例里又挖出合格的，
必须同时过 §3.2（题干不泄答案）与下面两道筛，**过不了宁可不要**：

```
① 无记忆时模型能不能靠通识答对？  能 → 剔除
② 答案是否唯一、能否字符串匹配？   否 → 剔除
```

编题凑数会稀释真实效应，而这个实验的全部价值就在那个效应上。

## 四、评分

```
A 类判对 = must_contain 全部命中 且 must_not_contain 全部未命中
```

匹配前统一小写、压缩空白。**零 LLM 裁判**——这是硬要求。

输出：

```
                 无记忆      有记忆      Δ（记忆增益）
Qwen3.5-2B       A1 ?/13     A2 ?/13     +?
Qwen3.5-4B       B1 ?/13     B2 ?/13     +?
Qwen3.5-9B       C1 ?/13     C2 ?/13     +?
Kimi-K3          K1 ?/13     K2 ?/13     +?
```

**Δ 那一列是阶梯论点的全部内容**，务必给出。按 §0.3b，**四档持平也是结果，照实报**。

### 🔴 n = 13，不要写 p 值当结论

McNemar 只对**两对**做，别把八格两两都跑一遍（多重比较，n 又没变多）：

```
A2 vs K1    主论点   2B+记忆   对  云端无记忆
A2 vs K2    张力题   2B+记忆   对  云端+记忆
```

且**只报不一致对的条数与方向**，例如「A2 对 K2 错 3 条，K2 对 A2 错 2 条」。

**n=13 不足以支撑显著性推断**，更不足以支撑「等价」这种主张——
等价检验需要的样本量远大于差异检验。11/13 的 Wilson 区间是 [64.6%, 95.5%]，宽到什么都证明不了。

所以决胜论点的表述必须是**描述性**的：

```
✅ 「在这 13 条环境特异任务上，Qwen3.5-2B+记忆 与 Kimi-K3 无记忆 打平（各 x/13）」
✅ 「记忆增益 Δ 在 2B/4B/9B 三档上基本持平，未见随规模衰减的迹象」
❌ 「实验证明小模型加记忆等价于云端大模型」
❌ 「Δ 随规模单调递减/递增」——四个点、每点 n=13，撑不起「单调」这个词
```

前两句站得住，后两句站不住。**报告里只准出现前两句那种写法。**

## 五、风险与降级

### 5.1 2B 可能连题都答不成形

2B 在中文长上下文下可能跑题、复读或空答。

**先跑 3 题冒烟**：A1、A2 两格都是 0 → 该规模不足以承载对照，**不要硬跑完 13 条**。

**四行阶梯把这条风险兜住了**——降级只是丢掉 A 行，
B/C 两行（4B、9B）与 K 行仍构成完整对照，主论点顺延为 `B2 ≥ K1`。

此时 A 行如实标注：

```
A 行：Qwen3.5-2B(Q4_K_M) 在 3 题冒烟中未能产出可判分答案，
      记为「该规模下不足以承载本任务」，不参与阶梯解读。
```

**这本身就是可交付的结论**——它给端侧最小可用规模划了一条下界。

### 5.2 注入的上下文可能超出 2B 的窗口

top-k=5 条知识单元，`render_case()` 每条约 300 字。**先量一次注入块的实际 token 数**，
超了就降到 k=3，**四行用同一个 k**（否则不是同一个实验）。

### 5.3 Kimi-K3 的网络波动

批次一实测出现过一次 8 秒超时。**每题失败重试上限 2 次，重试也计入 `runs.jsonl`**，
不要静默重跑到成功。

## 六、必须写进已知限制的五条

1. **本实验测的是「知识可得性」，不是「执行效率」**——因语料与 2B 能力所限，
   任务全为回答型，未覆盖多步执行与工具编排
2. **任务出自本项目自身的 86 条知识语料**，题目与知识同源；
   这保证了「答案在记忆里」，但也意味着**不构成对外部任务的泛化证据**
3. 检索配置固定为报告声明的系统配置，**`meta_oracle` 禁用**（标签泄漏，是上界不是能力）
4. **n=13，八格共用同一批题，仅为演示性对照，不具统计效力**——受语料规模所限（86 条知识单元中
   只有这些能出成答案唯一、可机器判分的题）。结论按 §四 只作描述性表述
5. 三档本地模型同族同代同 Dense、同机同运行时同量化档（§0.2 / §0.5）。
   thinking 模式（§0.2c）取值须写明。`wall_ms` 只在三档之间可比，
   **不得与 K 行的 API 延迟并列，也不得写成「本方案比云端快」**
