# 证明向量维度 —— 文件夹说明

本文件夹记录"银河麒麟 KYSDK embedding SDK 输出 768 维向量"这一事实的完整证明过程，以及在磐石不可变系统上让它跑起来所需的全部部署工作。

## 文件清单

| 文件 | 用途 | 什么时候看它 |
|------|------|-------------|
| `证明向量维度-KYSDK-Embedding-768-代码执行报告.md` | **核心证明报告**。说明如何证明、证据链是什么、三次独立复现的记录 | 想了解"768 是怎么证明出来的"、写技术文档/答辩材料时 |
| `前置步骤-不可变系统解锁与KYSDK部署命令手册.md` | **部署手册**。磐石不可变系统上从零跑通 embedding 的完整步骤，含全部踩坑记录与解法 | 需要在新机器上部署、或部署出问题需要排查时 |
| `emb_test.c` | 证明用的 C 程序源码（带完整中文注释），调用官方 SDK 输出向量维度 | 需要查看/修改验证程序时 |
| `restore_env.sh` | **一键恢复脚本**（手动版）。整机重启后运行它即可恢复全部环境（约 5~10 分钟） | 需要手动恢复、或自动恢复出问题时 |
| `restore_env_boot.sh` | **开机自动恢复脚本**（root 版）。已注册到 root 的 `@reboot` crontab，开机自动执行系统层恢复 | 一般不用手动碰，出问题时查日志 `/home/<USER>/restore_boot.log` |
| `start_runtime_session.sh` | **登录自启脚本**。已注册到桌面 autostart，登录桌面时自动拉起 `kylin-ai-runtime` | 同上，日志在 `/home/<USER>/runtime_session.log` |

## 快速上手

### 情况一：机器刚重启（现已配置为自动恢复，通常无需手动操作）

**已配置开机自动恢复**，重启后机器会自动完成恢复，正常情况下你只需要等几分钟再连接即可：

- 开机时：root 的 `@reboot` crontab 自动运行 `restore_env_boot.sh`，恢复 SSH、装回 SDK、启动 kytensor；
- 登录桌面时：autostart 自动运行 `start_runtime_session.sh`，拉起 `kylin-ai-runtime`。

**验证是否恢复成功**：

```bash
cat /home/<USER>/restore_boot.log     # 看开机恢复日志
~/emb_test                             # 应输出 768
```

**若自动恢复失败**，手动跑完整版脚本兜底：

```bash
bash ~/restore_env.sh
```

> 为什么每次重启都要恢复？因为磐石不可变系统的 `/usr` 分区改动**无法持久化**，这是系统设计使然，不是故障。完整结论与实证过程见部署手册第 7 节；自动恢复的配置方法见 7.4 节。
>
> **注意**：首次运行 `emb_test` 若报 `errCode: 24 Timeout`，是模型（339MB）仍在后台加载，等数十秒重跑即可，不是故障。

### 情况二：要在一台全新机器上部署

## 一句话总结结论

调用银河麒麟官方 embedding SDK（模型 `ensemble-embd_gte-base_uint8-text`），对中文文本向量化，输出维度为 **768**；该结论已在三次相互独立的环境状态下验证，向量数值逐位一致。
