## 〇、为什么要做成 HTTP 服务而不是直接调库

赛题 roadmap 阶段 04 的原话是「**将记忆能力封装为 OS Agent 可调用的接口**」。

做成服务还顺带解决三件事：

- **解耦运行位置**：向量化必须在麒麟上（KYSDK），但 pi 和小模型可以跑在别处
- **可演示**：视频里能直接展示"agent 发了什么查询、拿回了什么记忆"，不是黑盒
- **可开关**：有记忆 / 无记忆两组，差别只是调不调这个接口

## 一、记忆服务（麒麟机上常驻）

### 1.1 接口契约

```
POST /retrieve
  请求：{"query": "任务描述文本", "k": 5}
  响应：{
    "units": [
      {"doc_id": 12, "type": "case", "text": "...", "score": 0.83},
      ...
    ],
    "config": "all",
    "elapsed_ms": 74
  }

GET /health
  响应：{"ok": true, "index_size": 86, "config": "all", "backend": "kylin"}
```

**`config` 必须在响应里回显**——演示和实验都要能证明"用的是哪一套检索配置"。

### 1.2 内部实现要求

复用现成件，**不要重新发明**：

```
查询向量化   embedding_client.EmbeddingClient（常驻，别每次重连）
检索管线     measure_recall.retrieve_ablation(config, query, qvec, store, docs, max_k)
原文取回     DocStore
```

`retrieve_ablation()` 返回的是 `doc_id` 有序列表，**服务要再去 DocStore 把原文取回来**——
agent 需要的是知识内容，不是编号。

### 1.3 🔴 两条硬约束

**① `config` 禁止取 `meta_oracle`。**
那一档用标准答案自己的 `knowledge_type` 做过滤，是**标签泄漏**、是上界不是能力。
服务启动时若 `config == "meta_oracle"` 直接拒绝启动并报错。

**② `config` 必须与报告里声明的系统配置一致。**
做成启动参数，不要写死。报告说系统用哪一档，服务就跑哪一档。

### 1.4 服务落地

- 单文件、标准库 `http.server` 即可，**不要引入 web 框架**（麒麟上装包成本高、且不必要）
- 只监听 `127.0.0.1`，不对外
- 启动时预热一次 embedding（首次调用可能报 `errCode:24 Timeout`，那是模型在加载，不是故障）

## 二、pi 侧接入

### 2.1 契约（不绑定 pi 的具体 API）

```
每次 agent 准备行动之前：
    1. 拿【当前任务描述】调 POST /retrieve
    2. 把返回的 units 拼成一段上下文，插在系统提示之后、用户任务之前
    3. 记录本次注入了哪些 doc_id（写进运行记录，见 §四）
```

注入格式建议（分隔清楚，便于演示时指认）：

```
=== 相关记忆（来自本机知识库，共 N 条） ===
[1] (case) ...
[2] (workflow) ...
=== 记忆结束 ===
```

### 2.2 开关

```
--memory on   调 /retrieve 并注入
--memory off  完全不调，其余一字不变
```

🔴 **`off` 组不是"减掉一段提示词"，是"不调这个接口"。**
两组的系统提示、任务描述、可用工具**必须逐字相同**。

## 三、任务集　⏸ 批次二，等 C+D+E 完成后再做

> **本节及 §四 属批次二。** 在索引重建（C）落定之前不要开工——
> 出的题会因为索引变化全部作废。

### 3.1 出题方法（反向出题，保证答案在记忆里）

```
对每个知识单元问一句：
    「如果 agent 不知道这条，它会在什么任务上栽跟头？」
那个任务就是题，单元里的 fixed_input / tool_sequence 就是标准答案。
```

出完**人工复核**，剔掉两类：

- ❌ **通识题**（`netstat` → `ss` 这种，任何模型都会，测不出差异）
- ❌ 答案不唯一、需要主观评判的

### 3.2 文件格式 `tasks.jsonl`

**A 类 · 环境特异事实（10 条）**

```json
{"task_id":"T-001","type":"A",
 "prompt":"在这台机器上把 sshd 起来，告诉我用什么命令",
 "must_contain":["/etc/init.d/ssh"],
 "must_not_contain":["systemctl start ssh"],
 "source_unit":"case-012"}
```

`must_not_contain` **不是可选项**——它抓的正是"没有记忆时最容易给出的那个错答案"，
是这类题真正的区分器。

**B 类 · 沙箱状态达成（6 条）**

```json
{"task_id":"T-011","type":"B",
 "prompt":"把 workspace/logs 下所有 .log 归档到 workspace/archive/，保留原名",
 "setup_cmd":"...",
 "check_cmd":"ls ~/workspace/archive/*.log 2>/dev/null | wc -l",
 "expect":">= 3",
 "cleanup_cmd":"..."}
```

🔴 **只在 `~/workspace` 内操作，且必须可逆。**
**绝不设计"真把 sshd/KYSDK 弄坏再恢复"这类任务**——9 天到截止，机器出事赔不起。
踩坑知识全部用 A 类测。

**C 类 · 多步流程（4 条）**

```json
{"task_id":"T-017","type":"C",
 "prompt":"...",
 "must_contain":[...],
 "metrics":["tool_calls","failed_calls","wall_ms"]}
```

C 类测的是**效率**：大模型无记忆时多半也能做对，只是绕——差异全在这三个数上。

### 3.3 出题素材从哪来

⚠️ **现有索引主要是 Windows 开发期内容**（VS Code、v2rayN、plink、代理端口），
麒麟侧的知识（`share-kytensor-*` 服务名、`/usr` overlay、`unshare -m`、
恢复脚本在 USB 挂载点）**要看 C+D+E 重建后的索引里有没有**。

**先跑 `GET /health` 看 `index_size`，再从实际索引里出题。**
出不来 20 条就出 12 条，如实报——**不要为了凑数编题**。

## 四、运行记录与评分

### 4.1 每次运行落一条 `runs.jsonl`

```json
{"run_id":"...","task_id":"T-001","model":"qwen1.5b","memory":true,
 "answer_text":"...","tool_calls":7,"failed_calls":2,"wall_ms":41230,
 "injected_doc_ids":[12,45,7],"retrieval_config":"all"}
```

### 4.2 评分脚本 `score.py`

```
A 类：must_contain 全中 且 must_not_contain 全不中  → 对
B 类：跑 check_cmd，返回满足 expect             → 对
C 类：成功判据同 A/B，另报三个效率指标
```

**全部机器可判，零 LLM 裁判。** 这是硬要求，不是偏好。

### 4.3 输出

```
              无记忆        有记忆
Qwen1.5B      ?/20          ?/20      ← 主角
云端大模型     ?/20          ?/20      ← 天花板参照

分类型：A ?/10  B ?/6  C ?/4（含效率三指标）
```

**决胜的一句话**：「**小模型 + 记忆 ≈ 大模型无记忆**」。
成立则「能力源自机制设计、不依赖模型规模」有了硬证据。

## 五、🔴 四条纪律

**① 无记忆组必须同样允许跑命令调查。**
否则测的是"背没背过"，结论毫无意义。两组都能查，区别只是一组多注入了检索结果。

**② 两组提示词一字不差。**

**③ 每题独立会话。** 不许前一题的上下文帮到后一题。

**④ 不用 LLM 判 LLM 的输出。**

## 六、不要做的事

- ❌ 不要用 `meta_oracle` 配置（标签泄漏）
- ❌ 不要设计破坏性任务；B 类不出 `~/workspace`
- ❌ 不要碰 `~/.claude`（实验数据集本体，删了不可再生）
- ❌ 不要用通识题充数（会稀释真实效应）
- ❌ 不要把 embedding 对照（麒麟 vs BGE-M3）塞进这个 2×2
      —— 那属于检索层消融，用 227 题评测集测，混进来会变成 8 格且归因不清
- ❌ 不要在看到结果后回头改判据或改题
- ❌ 不要引入 web 框架、不要为此在麒麟上装包
