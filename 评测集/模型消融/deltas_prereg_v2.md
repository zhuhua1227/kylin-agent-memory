## 一、v2 相对 v1 改了什么，以及为什么这不是"看到结果后改判据"

### 改动 1：`render_case` 的「修复方式」段（`build_index_ablation.py`，不动冻结的 `render_units.py`）

- **v1**：`json.dumps(fixed_input, ensure_ascii=False)[:150]`。
- **问题**（v1 报告 §六.7，跑前 §二 已量过）：`fixed_input.command` 里的 claude 临时脚本路径
  （`C:\…\AppData\Local\Temp\claude\C--Users-…\<uuid>\scratchpad\x.py`，约 120 字符）把 150
  预算吃光，真正的修复动词（`timeout 500` / `pscp … /tmp/` / `base64`）被截没。**这不是
  v1 结果暴露的——是 v1 跑之前就在预登记里写下的已知缺陷。**
- **v2**：只清噪声、不加信息——把上述临时路径压成 `<临时目录>/`、`[REDACTED_LONG_TOKEN]…`
  压成 `<TOKEN>`，然后取 `.command` 截 400 字符（`error_text` 仍 300）。
- **影响面**：注入给模型看的记忆文本变了 → 所有有记忆格（A2/B2/C2/K2）必须重新生成；
  索引重新向量化 → 检索结果可能微调。无记忆格（A1/B1/C1/K1）的输入不依赖语料，
  但会用 v2 判据重新计分。**v2 全部 104 格重跑**（无记忆格在温度 0 下应逐字复现，
  当作一次可复现性自查）。

### 改动 2：6 条任务的判据（`tasks_v2.jsonl`，其余 7 条逐字不变）

原则：**接受任何"确实能解决这条特定报错、且在 86 条语料里有先例"的修法。** v1 的判据把
「有多个等价正解」的题锁死到其中一个，这是判据设计缺陷，不是模型的问题。逐条：

| 题 | v1 判据 | v2 判据 | 依据 |
|---|---|---|---|
| T-04 | `must_contain=[pscp, /tmp/]`；`must_not_contain` 含 `encode` | `must_contain=[any(pscp, "scp ", base64)]`；去掉 `encode` | surrogate 报错既能"传文件"（case-09）也能"base64 编码"（case-19/23），两种都是把命令避开 argv。`encode` 与 base64 方案字面冲突 |
| T-05 | `must_contain=[base64]`；`must_not_contain` 含 `\"` | `must_contain=[any(base64, /tmp/, 临时文件)]`；去掉 `\"` | 引号 EOF 既能 base64 也能写临时文件；写文件方案的示例代码里可能带 `\"` |
| T-06 | `must_contain=[python3 /tmp/, 脚本]` | `must_contain=[any(/tmp/, base64)]` | 把命令移出内联双引号串即可；**不接受"改用 while 循环"**（报错是 `[ ]` 测试括号，不是循环关键字，换 while 无效） |
| T-10 | `must_contain=[scp, pscp]`（两串同时） | `must_contain=[any(scp, pscp)]` | scp / pscp 同工具族，要求两串同现无意义 |
| T-11（边缘） | `must_contain=[-L]`（规范化成 `-l`，与 `curl -sL` 连写不匹配） | `must_contain=[any("-l ", "-sl", "--location", 正则 `curl…-…l`, "跟随重定向")]` | "跟随重定向"一个概念多种拼法 |
| T-13（边缘） | `must_contain=[timeout 500, 加大超时]`（两串精确） | `must_contain=[any(正则 `timeout ≥300`, 正则 "加大/延长超时到 ≥300")]` | 143 是 timeout 自发的 SIGTERM，修法就是加大到够大的值；**泛泛的 `timeout 60` 不接受**（还是不够）。原判据两串精确、且中文转述本就不在渲染文本里 |

**T-12 不放宽**：修法就是"用 `client/` 目录替 `server/`"，没有等价正解。模型给"find 搜路径"不是这条题的修法。

**T-07、T-13 仍标 edge / 单列**（T-07 疑通识、T-13 源单元未必被检索到）。v2 报告仍建议正式版剔 T-07。

## 二、v2 的预期（跑前写下，跑完只填空，不许事后挑）

v1 结论是"干净的解释乙"：Δ 随能力单调不减 `+1（2B）→ +4（4B）→ +4（9B）→ +5（K）`，
绝对水平被 render 截断压着。v2 修掉截断 + 放宽判据后，三种可能：

### 预期甲：各档 Δ 与绝对分**整体上移**，单调性大体保持

最可能。修 render 让 T-04/05/06/10/13 的答案串进入注入 → 有记忆格能多拿几条；
放宽判据让"等价正解"被认。若上移后仍是 2B < 4B ≈ 9B < K，**解释乙被 v2 加强**，
且"能力下限 ~4B"的结论更稳（因为现在 2B 是在"答案确实在记忆里"的条件下仍抽不出）。

### 预期乙：小档（2B）上移幅度**明显小于**大档 → 单调性更陡

也可能。若 render 修好后 4B/9B/K 的 Δ 猛涨、2B 几乎没动，说明"2B 抽取能力"是硬瓶颈，
**能力下限的结论进一步坐实**，可能要把下界从 4B 往上挪。

### 预期丙：无记忆格也跟着涨（判据放宽让"通识正解"更容易过）→ Δ 反而缩小

需要警惕的。放宽 T-11/T-13/T-04 的判据，可能让**无记忆**组靠通识多answer对几条
（如 K1 本就会 `curl -sL`、会"加大超时"）。若 A1/B1/C1/K1 涨得比 A2/B2/C2/K2 快，
Δ 会缩。**跑完必须逐格对比 v1↔v2 的无记忆分变化，看放宽判据到底喂给了谁。**
若 Δ 缩，说明这些题的"记忆增益"本来就有相当部分是判据过严凑出来的——如实报。

**三种都要能解释。跑完只在表里填数，对照本节，不许事后挑一个说成"符合预期"。**

```

2B            +1            ____          ____
4B            +4            ____          ____
9B            +4(非边缘)     ____          ____
K             +5            ____          ____
```
