> **状态**：**已确认冻结（2026-09-03）**。§六 四项均经使用者拍板。

## 〇、先纠正分界线口径

七天重挖（509 条候选）暴露一件事：**开发集与留出集不是同一个池子的两段。**

```
开发集 = 已冻结的 conflicts_eval.jsonl 36 对   ← Windows 侧挖出（2026-07-03 ~ 08-09 数据）
留出集 = D1~D7 的 480 条候选                    ← 麒麟侧挖出（2026-08-26 ~ 09-02）
```

麒麟这次挖掘**未覆盖 Windows 时期的历史数据**，所以按日期切出来的「开发集 28 条 / 正例 0」
其实是 08-25 的备采准备会话——**既非历史、亦非采集**。

**处理**：那 28 条 + 1 条无日期记录**全部排除**，理由写进报告。
分界线定义改为**按数据来源与采集窗口**，不再按单一池子的日期切分。

## 一、分层（机器可判，不许人工归类）

对每条候选，按顺序判，第一个命中即定层：

```
A · 数值漂移
    把 old/new 两段里的【数字、时间戳、PID、路径中的序号】全部替换成占位符后，
    两段文本【完全相同】 → A 层
    典型：anchor 读数、inventory 条目数、PID/uptime 变化

B · 环境失效
    source == "anchor"，
    或 old/new 含 sshd / kysdk / /usr / uptime / boot / PID 等环境关键词
    且时间跨越重启日（2026-08-29、2026-08-31）
    典型：重启导致 /usr 回滚、服务重新计时

C · 语义更正
    其余全部
    典型：结论被推翻、做法被更正 —— 需要读懂内容才能判
```

**C 层是唯一有说服力的那层。** A 层"数字变了"不需要任何语义判断，
B 层"重启了所以旧的不成立"也基本是结构性的。

> ⚠️ **如果 C 层样本很少，那本身就是要如实报告的结论**——
> 说明这七天的数据"量大但难度不够"，而不是用 A 层的高分掩盖过去。

## 二、抽样（数量在此写死，看到分层结果后不许改）

### 2.1 结构正例（`structural_label == candidate`）

| 层 | 抽取条数 | 不足时 |
|---|---|---|
| **C 语义更正** | **15** | 全取，并在报告里写明「C 层仅 N 条」 |
| **B 环境失效** | **8** | 同上 |
| **A 数值漂移** | **7** | 同上 |
| 合计 | **30** | |

### 2.2 结构负例（`structural_label != candidate`）

**随机抽 30 条**，不分层（负例的分层没有对应意义）。

### 2.3 抽样方式

```
随机种子固定为 20260903
抽样脚本提交进 git，与结果一同交付
每条记录抽中时的 conflict_id，写进抽样清单
```

**先生成抽样清单并提交，再开始裁决。** 清单一旦提交不许重抽。

## 三、裁决（沿用已验证过的盲测协议）

```
① 打乱顺序
② 只显示 old / new 两段原文
   ❌ 不显示 structural_label / conflict_id / 时间戳 / 来源
   （时间戳必须藏 —— 它泄露"是否跨天"，正是要防的结构暗示）
③ 判断依据：《冲突判定标注规范》v1.0.1 §五 判定流程
④ 🔴 混入 5 条诱饵：从冻结集已确认的 19 条正例里抽
   —— 诱饵漏判任何一条，整轮作废重来
⑤ 每条记录裁定 + 不一致时写一句理由
```

**标注者**：使用者本人。60 条约 2 小时，可分两次。

## 四、🔴 三条不许违反的纪律

**① 抽样清单提交在前，裁决在后，看指标在最后。**

```
写协议 → 分层 → 抽样并提交清单 → 盲测裁决 → 【这时才算准确率】
```

任何一步提前看到下一步的结果，这批留出集就作废了——**而且再也造不出第二个**。

**② 裁决完不许回头改规则。**

规则冻结在 commit（哈希 `bebd5ccd`）时，D1~D7 数据一条都还不存在。
这是整个「规则先于数据」论证的支点。掉了就如实报 + 写成诊断。

**③ 分层准确率必须分开报，不许只报合计。**

```
A 层准确率 / B 层准确率 / C 层准确率 / 加权合计
```

只报合计，等于用 A 层的高分稀释 C 层——**那正是"把题目变简单当成系统变好"的变种**。

## 五、报告怎么写

```
开发集（n=36，规则在其上开发）    ：35/36 = 97.2%，CI 下界 85.8%
留出集（n=60，规则从未见过）      ：X/60 = ?，CI 下界 ?
  · C 语义更正层  ?/15
  · B 环境失效层  ?/8
  · A 数值漂移层  ?/7
  · 负例         ?/30
合并（n=96）                     ：Y/96 = ?
```

**三个数都报。** 合并那个是全部标注数据的成绩，通常作头条；
留出集那个是泛化证据；开发集那个如实标注"规则在其上开发过"。

⚠️ **若留出集显著高于开发集，不要当成"泛化良好"** —— 更可能是
A/B 两层拉高了平均。**那时候更要看 C 层单独的数。**
