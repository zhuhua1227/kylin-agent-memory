## 二、23 处「真实姓名/主机名」：不改，是承重项

`test_detectors.py:793` 的 `BY_DESIGN` 白名单已经登记了这两个文件：

| 文件 | 处数 | 登记理由（引自 `test_detectors.py`） |
|---|---|---|
| `可复现性体系/anchor_issue_snapshot.json` | 20 | GitHub issue 锚定快照，**URL 与作者字段必须可被第三方公开核验**；表内第 4 项即该 GitHub 用户名，随仓库 URL 天然公开 |
| `评测集/说明报告.md` | 3 | 正文引用上述锚定 issue 的地址，同上 |

**这是锚定机制的承重部分**：第三方要靠这个用户名去 GitHub 核验 issue 真实存在。
**删掉等于把可核验性拆掉，比留着更糟。**

`scan_identity.py` 已同步这份 `BY_DESIGN`，命中会标 `✅设计内公开` 并不计入残留。
**`test_detectors.py` 是权威**，两处若不一致，以它为准。

## 三、保留 + 登记：逐条风险定性

这些**不改**，但要在 `脱敏/脱敏说明.md` 里逐条写明为什么。

### 3.1 冻结文件里的 13 处

`.gitattributes` 标 binary 的 17 个文件**字节不得变**——它们是 `claims.json`
122 条主张的锚。改一个字节，`generate_manifest.py` 全部失配、`reproduce_L1.py` 全红，
「规则先于数据」这条论证当场作废。

**命中项逐条定性**：

| 命中项 | 是什么 | 实际风险 | 结论 |
|---|---|---|---|
| `a638…b080`、`129f…44d5`（40 位） | GitHub OAuth **device_code** | 一次性授权码，**约 15 分钟即过期**，早已失效，无法用于任何访问 | 保留 |
| `178c…1d6a`（20 位） | GitHub OAuth **client_id** | **设计上公开**——每个授权 URL 里都带着它，本就不是机密 | 保留 |
| `192.168.100.3`（`query.tsv`、`eval_set_frozen.json`） | RFC1918 内网地址 | **不可路由**，不构成任何访问途径 | 保留 |

**四项都不构成可利用的凭据或访问途径**，而破坏冻结的代价是整套可复现性体系。
**这个取舍要写进说明，不要默默留着。**

### 3.2 非冻结文件里的内网 IP（19 处）

RFC1918 不可路由，且本仓已有大量 `[REDACTED_IP]` 占位——这 19 处是漏网的。

```
建议：不处理，在说明里写明"RFC1918 内网地址保留，不构成访问途径"
若要处理：必须【整批】换成占位符
```

🔴 **不许改一半**。部分脱敏 + 假名不一致，反而给了相关性反推的入口——
那比不脱敏更糟。**一致性比彻底性重要。**
